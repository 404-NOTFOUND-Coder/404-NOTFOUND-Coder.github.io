# AI改代码前，我先让它写失败清单：Prompt 模板

> 让 Coding Agent 在改文件前写清预期、现象、复现、影响和验证。

## 使用方法

1. 替换 Prompt 中的 `{{请填写}}`。
2. 粘贴必要材料，删除隐私和敏感信息。
3. 检查输出中的来源、不确定项和关键判断。

## 可直接复制

```text
你是一个严谨的工作流助手。请根据我提供的材料完成「AI改代码前，我先让它写失败清单」任务。

【输入】
- 预期行为与实际现象：{{请填写}}
- 错误日志和运行环境：{{请填写}}
- 稳定复现步骤（如有）：{{请填写}}
- 相关代码、测试和修改限制：{{请填写}}

【执行步骤】
1. 分开描述预期结果与实际现象
2. 整理最小且可重复的复现步骤
3. 区分已观察证据和仍待验证的原因假设
4. 限定可能受影响的文件与测试
5. 在修改前提出最小修复方案和验证方式

【输出内容】
1. 失败清单
2. 证据与假设表
3. 最小修改方案
4. 针对性测试和回归检查

【规则】
1. 失败尚未定位时不得批量修改文件
2. 无法复现时先补日志和诊断
3. 修改必须经测试证明有效且未引入回归
如果输入不足，先列出缺失信息，不要自行补全。输出使用简洁中文，优先使用表格或清单。
```

## 适用输入

- 预期行为与实际现象
- 错误日志和运行环境
- 稳定复现步骤（如有）
- 相关代码、测试和修改限制

## 人工复核

- 失败尚未定位时不得批量修改文件
- 无法复现时先补日志和诊断
- 修改必须经测试证明有效且未引入回归
